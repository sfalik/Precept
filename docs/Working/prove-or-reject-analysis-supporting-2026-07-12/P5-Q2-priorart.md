# Research Brief: Legibility Boundaries in Sound Static Verification — Prior Art Beyond Precept

## 0. What I'm holding fixed vs. what I'm challenging (per the framing)

**Held fixed (identity-level, philosophy-anchored, not up for revision in this brief):**
- Prevention/structural-impossibility (`philosophy.md:49-57`)
- Determinism, one-file completeness (`philosophy.md:22, 58`)
- Honesty about approximation (`philosophy.md:23-25`)
- **Legibility of proof reasoning itself** — spec:225's *stated rationale* ("proof witnesses must be structured data, not opaque solver traces… the author is never confronted with an unexplainable verdict") is the anchor. This is the actual identity commitment.
- Soundness-over-completeness and "proven violations only" (`precept-language-spec.md:221-223`) — a decision procedure that can silently produce a false "safe" is disqualified regardless of legibility.

**Challenged (current spec text, not identity):**
- `precept-language-spec.md:225`'s **operational rule**, as currently written: *"opaque solvers are rejected on principle… this is why SMT/Z3 solvers are excluded even when they could prove more."* This collapses two different things — (a) the search procedure that *finds* a proof, and (b) the witness artifact the proof engine *surfaces* — into one ban on a named tool class. The prior art below shows those two things are separable, and separating them is what the legibility rationale in the same paragraph actually requires.
- `collection-types.md:860`'s "map/filter/reduce/sum… held back" — not re-litigated here in depth (out of scope of this brief), but flagged because a legible-certificate boundary for nonlinear/aggregate reasoning bears directly on whether `sum` becomes provable rather than merely computable.

I did not find a locked decision anywhere in the corpus that specifically forecloses "legible non-SMT decision procedures" (Fourier-Motzkin, SOS, Handelman) — spec:225 names "SMT/Z3" as the excluded class, not certificate-producing algebraic methods. So this brief treats that as Tier 2 (new-surface, no direct spec conflict) for the *specific mechanisms*, and Tier 3 (spec conflict) only for the *general principle* that "solver" ⟹ "opaque."

PLE itself is a *transparent, terminating rewrite procedure* (not a heuristic search) — its output is a deterministic unfolding trace, which is a materially different (and more legible) shape than generic quantifier-instantiation heuristics in SMT. |

**Cross-system pattern:** every one of these systems, when auto-proof fails on nonlinear/hard goals, converges on the *same three-tier discharge shape*: (1) a **named, reusable, human-checkable lemma** (SPARK Lemma Library / ACSL lemma / F\* Math.Lemmas — all structurally identical: a proved fact with a name, invoked like a library call); (2) an **explicit calculational chain** (Dafny `calc` / Liquid Haskell `?`-proof) — arguably the single most Precept-compatible artifact found, since it's literally "the algebra, shown"; (3) an **unsound, explicitly-marked escape** (`pragma Assume` / Dafny `assume`) that every system treats as a liability to be minimized and audited, never as a hidden default. None of these systems ever make the *raw SMT resolution trace* the user-facing artifact — that trace exists internally (and is sometimes machine-checkable via proof-producing solvers, see §3) but is never what a human reads.

## 2. Certificate-based methods, ranked by power vs. legibility

This is the section that answers the core Precept question directly: **is there reasoning stronger than interval arithmetic whose *output* — not its search procedure — is an inspectable, structured witness?**

### 2.1 Linear arithmetic: Farkas' lemma / Fourier-Motzkin elimination
- **Farkas (1902)**, constructively realized via **Fourier-Motzkin elimination** (Fourier 1826; rediscovered Motzkin 1936). For an infeasible system of linear inequalities, the certificate is an explicit **nonnegative linear combination of the hypotheses that sums to a manifest contradiction** (e.g., `0 ≥ 1`). The witness is a short list of nonnegative multipliers — checkable by a domain reader doing ordinary arithmetic, with zero appeal to solver internals.
- **This is strictly more powerful than interval arithmetic**: interval arithmetic treats each variable independently and loses correlations ("the dependency problem" — a variable appearing twice in an expression is double-counted as independent uncertainty). Farkas/FM certificates *correlate* multiple linear constraints across multiple fields simultaneously — e.g., proving `X - Y > 0` from `rule X > Y` (exactly the relational-reasoning case already implemented per `precept-language-spec.md:256`) is a trivial Farkas certificate, and the *general* multi-field linear case (proving a combination of several rules jointly implies a bound) is exactly what Fourier-Motzkin generalizes to, with the same certificate legibility, where Precept's current single-pass/depth-bounded relational reasoning (§0.4, no "transitive chasing of a third field," `:256`) stops short.
- **Verifiable independent of the algorithm that found it**: an FM/Farkas certificate can be checked by a simple, dumb arithmetic pass even if produced by a full SMT solver's internal Simplex engine — this is the crux distinction the current spec:225 conflates. Z3 and CVC5 *can* and do emit Farkas certificates for their linear-real-arithmetic (LRA) theory solver, but spec:225 excludes them wholesale as "SMT," discarding a legible-certificate mode that happens to live inside an SMT solver's plumbing.

### 2.2 Polynomial nonlinear arithmetic: Positivstellensatz / Sum-of-Squares (SOS)
- **Parrilo (2000 PhD, Caltech; building on Stengle 1974, Schmüdgen 1991, Putinar 1993 Positivstellensätze)**: a polynomial `p` is proved nonnegative by exhibiting `p = Σᵢ qᵢ²` — an explicit sum-of-squares decomposition. **Verifying the identity is pure polynomial multiplication/coefficient comparison** — "a purely syntactic, easily verifiable certificate" (per the SOS literature surveyed above) — independent of trusting whatever semidefinite-programming solver *found* the `qᵢ`.
- This is the cleanest possible instance of **"opaque search, legible certificate."** The SDP solver that searches for the decomposition is a numerical black box; the *output*, once found, is checked by a domain reader (or a trivial CAS) multiplying out polynomials and comparing coefficients — no different in kind from checking someone's algebra homework.
- **Handelman's theorem (1988)** is the LP-relaxation sibling: for a polynomial positive on a compact polytope defined by linear constraints `gᵢ ≥ 0`, the certificate is a **nonnegative linear combination of products of the `gᵢ`** — found by linear programming (cheaper, more transparent search than SDP) and, again, checked by expanding the product and comparing coefficients.
- **This directly targets Precept's nonlinear obligations** — `sqrt` non-negativity, `pow` exponent safety, and any future nonlinear rule/guard combination (§0.6 items 3-4, `:205-206`) — with certificates that are strictly more powerful than interval containment (they can prove facts no interval bound can, e.g., `x² - 2xy + y² ≥ 0` for all real `x,y`, which interval arithmetic cannot show without bounding `x` and `y` first) while remaining independently, arithmetically checkable.

### 2.3 Interval arithmetic (Moore, 1966) and affine arithmetic (Comba & Stolfi 1993; de Figueiredo & Stolfi 2004 survey)
- **Interval arithmetic** is Precept's current baseline (§0.6 item 1) — sound, trivially legible (a `[lo, hi]` pair anyone can read), but weak: it treats every occurrence of a variable as an independent unknown, so `x - x` over `x ∈ [0,10]` is computed as `[-10, 10]` rather than the true `0` (the "dependency problem").
- **Affine arithmetic** represents a quantity as `x₀ + x₁e₁ + x₂e₂ + … + xₖeₖ` where the `eᵢ` are shared symbolic noise terms in `[-1,1]`. Two affine forms that share a noise symbol are *correlated*, so `x - x` correctly collapses to `0`. This is genuinely stronger than interval arithmetic on any expression with repeated sub-terms (extremely common in `.precept` field arithmetic — e.g., `balance - balance * rate` style expressions) and its representation (a list of coefficients against named noise symbols) is a moderate step down in legibility from a plain interval but still a structured, inspectable data shape — arguably comparable in legibility cost to what Precept's proof attribution already carries (`:231`, "constraints and rules that contributed").
- Non-affine operations (multiplication of two non-constant affine forms, `sqrt`, etc.) introduce a fresh "linearization noise" term bounding the nonlinear error — this is where affine arithmetic's legibility starts to degrade (the new noise term's bound is itself a derived numeric fact, one layer removed from something a domain expert reads directly), and where SOS/Positivstellensatz certificates (§2.2) become the more legible choice for genuinely nonlinear (not just correlated-linear) facts.

### 2.4 The counter-example: quantifier elimination via CAD is powerful but NOT legible
- **Tarski (1951)** proved real-closed-field arithmetic (full nonlinear polynomial arithmetic, any quantifier nesting) decidable in principle. **Collins (1975)**'s **Cylindrical Algebraic Decomposition** made it practical(ish). This is *more decision power* than anything above — it can in principle decide any polynomial inequality over the reals, quantifiers included.
- But its output is a **cell decomposition whose size is doubly-exponential in the number of variables** — the search results above are explicit: "the quantifier-free expression has length doubly exponential in the number of quantifiers." **This is the load-bearing negative case for the whole brief**: CAD is *sound*, *complete*, *far more powerful* than interval or even SOS reasoning, and yet its certificate is categorically illegible — not "hard to read," but astronomically sized for anything beyond a handful of variables. **Power and legibility are independent axes; maximizing one does not maximize the other.** This is direct evidence against equating "solver-free" with "legible," and equally direct evidence against "more powerful" as a synonym for "acceptable."

### 2.5 Proof-producing SMT and the LCF/de Bruijn distinction
Modern SMT solvers (Z3, cvc5) *can* emit independently-checkable proof certificates (LFSC format, resolution/CDCL(T) proof DAGs — Barrett et al.'s line of work on cvc5 proof production). These satisfy a **machine-checkability** bar — a small independent checker can verify the proof without trusting the solver (the classical LCF/de Bruijn-criterion property). **This is not the same property Precept's spec:225 rationale asks for.** Precept's stated bar is legibility "to authors… and to AI agents" (`:225`) — i.e., *human-inspectable*, not merely *independently machine-checkable*. A cvc5 resolution proof over hundreds of ground ε-instantiations is machine-checkable but not something a domain expert reads. This is the reason SMT search, even proof-producing SMT, still fails Precept's bar for *general* nonlinear goals — but it is also the reason the Farkas-certificate case (§2.1) is different in kind: for the LRA theory specifically, the "resolution proof" *is* short and *is* a Farkas combination, which is human-legible. **The dividing line is per-theory certificate shape, not "solver vs. not."**

## 3. Synthesis — where legibility, not spec:225's line, should draw the boundary

**The single finding that should reframe the spec line:** across SPARK, Frama-C, Dafny, F\*, and Liquid Haskell, the actual working distinction the field has converged on is **not** "solver vs. no solver." It is:

> **Is the discharge artifact a compact, self-checking structure a domain reader can verify by direct arithmetic/algebra (a certificate) — or is it a byproduct of a search process that only the search process itself trusts (a trace)?**

By that test:
- **Legible, and independent of what found them**: Farkas/Fourier-Motzkin combinations (linear), SOS/Positivstellensatz/Handelman decompositions (polynomial nonnegativity over polytopes), Dafny-`calc`/Liquid-Haskell-`?`-chain calculational proofs (arbitrary algebraic identities, author-composed), affine-arithmetic noise-symbol forms (correlated linear/near-linear bounds), named reusable lemmas (SPARK/Frama-C/F\* pattern — a proved fact invoked by name, itself built from the above).
- **Illegible regardless of soundness**: raw SMT resolution/CDCL(T) traces (even when proof-producing and machine-checkable), CAD cell decompositions, heuristic nonlinear (NRA) quantifier-instantiation search.

**Answer to the key question, directly:** yes — Farkas/Fourier-Motzkin certificates and SOS/Positivstellensatz/Handelman certificates are both **strictly more powerful than interval arithmetic** (they prove facts interval containment structurally cannot — cross-field correlation for the former, genuine polynomial nonnegativity for the latter) **while producing an inspectable, checkable witness** that satisfies "structured data, not opaque solver traces" (`:225`) at least as well as the interval-containment witnesses Precept already ships. Affine arithmetic sits in between: more powerful than interval, moderately legible, and useful as a cheaper default before reaching for SOS. Calculational-chain proofs (Dafny/Liquid-Haskell style) are a *different* axis entirely — not a decision procedure but an **author-composed structured proof**, which maps unusually well onto Precept's domain-expert-author premise (§0.8): a `because`-clause-style chain of named algebraic steps is arguably *more* legible to that specific audience than a numeric interval, not less.

**What this means for spec:225, stated as a challenge with the required four legs:**

- **What it currently says** (verbatim): *"Opaque solvers are rejected on principle. …This is why SMT/Z3 solvers are excluded even when they could prove more: opaque proof witnesses violate the inspectability commitment."*
- **Rationale for revising**: the ban targets a tool class (SMT/Z3) when the actual identity commitment (stated in the same sentence) is about witness legibility. The prior-art survey shows every comparator system separates "what found the proof" from "what the author/tool sees," and several certificate families (Farkas, SOS, Handelman) are strictly more powerful than Precept's current interval baseline while meeting the stated legibility bar as well as intervals do.
- **Alternatives considered and rejected**: (a) leave spec:225 as-is and accept interval arithmetic (plus the existing single-pass relational reasoning) as the permanent nonlinear/multi-field ceiling — rejected as leaving provable-in-principle facts (cross-field correlation, nonlinear nonnegativity) permanently unprovable for reasons unrelated to legibility; (b) adopt full SMT (Z3/CVC5) as the proof backend and rely on proof-producing (LFSC) output for "legibility" — rejected because machine-checkability (§2.5) is not the same property as human/agent legibility that `:225` actually asks for, and general nonlinear SMT search has no compact certificate shape at all (only linear-theory fragments do).
- **Precedent**: SPARK Lemma Library, Frama-C ACSL lemmas/lemma-functions, F\* Math.Lemmas (named-proved-fact pattern); Dafny `calc` / Liquid Haskell `?`-proofs (calculational-chain pattern); Parrilo 2000/Handelman 1988 (certificate-not-search pattern); Farkas 1902/Fourier-Motzkin (linear correlation pattern); CAD (Collins 1975) as the explicit negative case showing power and legibility are independent.
- **Tradeoff being accepted if the line is redrawn**: a certificate-format boundary ("the witness must be a bounded-size, independently-checkable algebraic object in a closed enumerable family: interval, affine form, Farkas combination, SOS/Handelman decomposition, or an author-composed calculational chain") is *harder to state and implement* than a blanket tool-class ban, and requires deciding, per obligation family, which certificate shapes are in scope — real engineering work, not a one-line policy. It also means the proof engine's "no SMT" self-description becomes more precise but less simple to explain ("we don't do opaque search-and-trust; we do enumerable certificate-checking, some of which uses the same underlying algebra an SMT solver's theory-solvers use").

This is a Tier 3 item under the Pre-Design Owner Consultation gate — `precept-language-spec.md:225` is an explicit locked "no X" statement — so this brief surfaces the conflict and the candidate reframing; it does not resolve it. The candidate reframing on the table for conversation: replace "opaque solvers are excluded" with a **certificate-family allowlist** (interval, affine, Farkas/Fourier-Motzkin, SOS/Positivstellensatz/Handelman, author-composed calculational chains) defined by the checkability property, explicitly leaving open whether any of those families gets implemented via an off-the-shelf SMT/LP/SDP backend internally, since the identity commitment is about what the author/agent sees, not what computed it.
