# Q2 — Expressiveness & Proof-Engine Limits: Does pure prove-or-reject remove capability?

**Verdict up front:** No computation class is removed. After filtering the known "blindnesses" through the design-ceiling test, the merely-unprovable cell shrinks to two families — unbounded-operand flows and unstated nonlinear cross-field correlations — and both are FORCEABLE: the same computation is expressible and provable after an annotation the language already has surface for. What pure prove-or-reject genuinely removes is not a computation but **one authoring mode**: the ability to declare a policy band on a derived value while leaving the out-of-band case unspecified. Every band on a derived value must ship with an authored in-band strategy (guard-refusal, clamp, or source bound). Whether that mode is "legitimate expressiveness" is exactly the Q1 posture question, not an expressiveness fact. On the decidability ceiling: comprehensiveness is unreachable (hard undecidability + the legibility principle), but **forceability is total** — the ceiling limits what the engine can *discover*, never what the author can *write*.

---

## 1. The decidable fragment at the design ceiling

The ceiling is set by principles, not by today's `NumericInterval`/octagon implementation and not by the (revisable, agent-authored) locked relational design. Three principles define it:

- **Loop-free, branch-free, pure, finite, single-file** (`precept-language-spec.md:158-172`, §0.4: no loops/fixpoint/widening, no reconverging flow, expression purity, closed type vocabulary, no separate compilation). Consequence: **every definition-derived value is a finite composition of pure language expressions over committed pre-state and governed args.** The strongest postcondition of any action chain is itself a quantifier-free Precept expression (substitution along a linear walk — `:164` "a linear walk, not a dataflow graph"). The undecidability that plagues general verification (loops ⇒ invariant inference ⇒ halting) is designed out of the language.
- **Sound-over-complete, proven-violations-only, tri-state** (`:221,223,229`).
- **Legible witnesses; SMT/Z3 excluded** (`:225`). Note the precise wording: the exclusion is of *opaque proof witnesses* ("Proof witnesses must be structured data, not opaque solver traces"), not of decision procedures per se. This matters below.

**The ceiling fragment** — what a fully-designed solver-free engine can decide:

1. **Exact interval images of every catalog operation over bounded operands.** `+ − * / %`, `pow`, `sqrt`, `min/max/abs/clamp`, rounding, string-length, count intervals, unit-normalized comparison (`:203-207`). All catalog numerics are piecewise-monotone, so interval images are *exact*, including nonlinear ones: `[0,50] * [0,20] = [0,1000]` is a proof, not an approximation. There are **no transcendentals to defeat** — the function catalog is closed (`:1559-1616`, §3.7: no exp/log/sin), so "transcendental unprovability" is moot *by language design*.
2. **Symbolic sequential composition over chains** (no join points ⇒ substitution-based strongest-postcondition, terminating, no fixpoint — sanctioned by `:174`: "single-pass validation… without the lattice infrastructure").
3. **Relational difference-bounds (octagon, `±x±y ≤ c`)** — including field equality `A == B` as `x−y≤0 ∧ y−x≤0`.
4. **Expression-congruence discharge** — the ceiling's most important and least-implemented capability: a governed rule or in-scope guard whose expression matches (after substitution) the checked predicate discharges the obligation *regardless of arithmetic class, including nonlinear*. Governance makes every declared rule true of every committed state (`:268-272`, §3A.4 working-copy atomicity), so a declared rule is a sound premise at every operation entry. The shipped engine already does the primitive form (rule-sourced relations, `:256`); generalizing match-after-substitution is symbolic, solver-free, and maximally legible (the witness is "your own rule/guard, verbatim").
5. **Concrete evaluation over statically-known values** (the default value-fold — decides equality/string/boolean/multi-field shapes on concretes; `bounds-only-constraint-enforcement-2026-06-05.md:51-58`).

**Classifying the cited "blindnesses" (`bounds-only…:40-47`) — the prompt's required filter:**

| Blindness (snapshot of current impl) | Ceiling classification |
|---|---|
| Field equality `A == B` | **MERELY-UNIMPLEMENTED** — octagon-representable as two inequalities; value-fold already decides it on concretes |
| Disjunction `A < 0 OR A > 100` | **MERELY-UNIMPLEMENTED** — finite interval unions (disjunctive completion) are solver-free and legible; loop-freedom bounds the blowup; guard rows already *are* per-row disjunction |
| 3-variable sums `A + B ≤ C` | **MERELY-UNIMPLEMENTED, with one interpretive fork** — linear-rational entailment is decidable by Fourier–Motzkin elimination (deterministic, terminating, produces explicit certificate chains — a *legible* witness). It is foreclosed only if the owner reads `:225` broadly as banning any decision procedure rather than opaque witnesses; the current text bans opacity, not decidability. Owner call — flagging, not asserting. Even under the broad reading, verbatim-stated 3-var rules discharge by congruence (item 4). |
| Non-numeric domains (string/bool/choice/currency) | **MERELY-UNIMPLEMENTED** (finite-domain enumeration is decidable and legible) — and largely irrelevant to this cell: declared bounds are numeric/length/count |
| Modulo/parity (`N % 2 == 0`) | **MERELY-UNIMPLEMENTED** — congruence domains (Granger 1989) are standard solver-free abstract domains; `%` also has the exact image `[0, k−1]` |

So most of the cited blindness list is snapshot, not ceiling. **The FUNDAMENTAL residue is exactly two things:**

- **(F-1) Deriving unstated nonlinear consequences.** Nonlinear *integer* entailment is undecidable for any system (Matiyasevich 1970 — Hilbert's 10th); nonlinear *real/decimal* entailment is decidable (Tarski 1951) but only via CAD-class procedures (Collins 1975) whose witnesses are exactly the opaque-solver shape `:225` excludes. The engine can *check* a nonlinear fact stated verbatim (congruence) and *compute* nonlinear interval images over bounded operands; it cannot *derive* an unstated nonlinear cross-term consequence.
- **(F-2) The intent gap** — wrong-but-in-band formulas: "undecidable for ANY compile-time system — intent is not in the artifact" (`compile-time-niche-decision-packet-2026-06-10.md:90-92`). Noted for completeness; by construction it is **not in this cell** (in-band values violate no bound).

## 2. Exactly when nonlinearity defeats the engine

"Nonlinear ⇒ unprovable" is false. At the ceiling, nonlinearity defeats the engine in precisely two situations:

1. **An operand is unbounded** — ⊤ absorbs: `[0,∞) × [0,20] = [0,∞)`. This is the dominant real-world case (84% of corpus numeric fields unbounded, `niche-packet:129`; 214:10 unbounded:bounded money, `bounds-only…:120`).
2. **The needed fact is a cross-field nonlinear *relation* not stated verbatim** — e.g. rule `AvgCost * Quantity <= 1000` declared, but the write is `set Total = AvgCost * Quantity + Fee`: closing the gap needs one nonlinear derivation step (F-1).

It does **not** defeat: bounded-operand products/powers (exact monotone images), `sqrt` (monotone), sign-definite division (proof-carrying anyway, out of cell). And **accumulation is not in the cell at all**: for `set Balance = Balance + amount`, the band itself is a sound inductive premise (the committed state satisfied constraints — `:272`; atomicity §3A.4), so the entry fact `Balance ∈ [0,max]` is legitimate; `Balance + amount` then *genuinely exceeds the band for some reachable in-band values* — there is a concrete violating input sequence. That is **genuinely-violable, not merely-unprovable**; rejection is a true positive and the demanded guard is a *correctness fix*, not lost expressiveness. The only merely-unprovable accumulations are those protected by a cross-field invariant — which is expressible as a rule and therefore forceable (row 3 below).

## 3. Unprovable computation classes — UNWRITABLE vs FORCEABLE

Universal escapes that exist at the ceiling: **E1 self-guard** — because chains are loop-free and pure, the post-value of any derived write is itself a language expression over pre-state+args, so `when <that expression> <= max` always exists syntactically and discharges by congruence; **E2 clamp** — `clamp(value, lo, hi)` is shipped catalog surface (`precept-language-spec.md:1574`) with interval image `⊆ [lo,hi]` by definition; **E3** bound the source; **E4** restate the invariant as a governed rule (ingress-enforced ⇒ sound premise).

| # | Class (all at design ceiling) | Concrete fragment | Tag | Forcing move |
|---|---|---|---|---|
| 1 | Unbounded-operand arithmetic (linear or nonlinear) into a band | `field AvgCost money` (no max); `Total <- AvgCost * Quantity`; `Total max '1000000 USD'` | **FORCEABLE** | E3 (`AvgCost max …`) or E1 (`when AvgCost * Quantity <= '1000000 USD'`) or E2 (`clamp`). Note E1/E2 avoid inventing a false domain ceiling on the open-ended input — the write-site cap *is* the policy band's meaning, so the "unnatural money max" objection (`bounds-only…:122`) dissolves at the write site. |
| 2 | Unstated nonlinear cross-field correlation (F-1) | rule `AvgCost * Quantity <= C` declared; write is `set Total = AvgCost * Quantity + Fee` into `max C+F` | **FORCEABLE** (derivation FUNDAMENTAL; statement trivial) | E1 with the exact write-site predicate — congruence needs no arithmetic |
| 3 | Invariant-protected accumulation | `set Balance = Deposits − Withdrawals` into `[0, max]`, safe only because withdrawals are elsewhere guarded `<= Balance` | **FORCEABLE** | E4: `rule Withdrawals <= Deposits` (a difference-bound — octagon-representable!) plus `rule Deposits − Withdrawals <= max`; both governed at ingress, carried as premises |
| 4 | 3+-var linear relations (if `:225` read broadly) | `rule Refund + Forfeit <= Paid`; write `set Remaining = Paid − Refund − Forfeit` into `[0, max]` | **FORCEABLE** | E4/E1 verbatim congruence; or resolve the interpretive fork toward FM certificates and it proves natively |
| 5 | Non-convex facts (≠, disjunction) feeding a band | `rule Tier != 3`-dependent derived write | **FORCEABLE** (and merely-unimplemented anyway) | guard rows are native disjunction |
| 6 | Mid-chain derived write after a mutation in the same chain | `set A = f(...); set C = g(A, B)` into band — the row-entry guard fact about `g` is invalidated by the write to A (`:233`, sequential proof flow) | **FORCEABLE** | E1 with the *substituted* composition `when g(f(...), B) <= max` — always expressible (purity + no joins); or restructure/split. Cost: guard-expression size can be hostile to the §0.8 domain-expert audience. Symbolic substitution discharge at the ceiling erases even that. |
| 7 | `now()`-derived writes into temporal bands | `set FiledAt = now()` into `max Deadline` | **FORCEABLE iff** `now()` is operation-snapshot-stable (one sample per operation). Determinism (`:96`) pushes that way, but I did not find it pinned in the spec — **flagged as the one semantics prerequisite the forceability theorem depends on.** If `now()` re-samples per call, the self-guard cannot pin it and this row becomes a genuine unprovable residue. |
| 8 | History-dependent invariants ("sum of all past deposits") | — | **vacuous** | Facts outside the file can't help proof (`:227`) — but computations outside the file's fields don't exist either. Nothing to write ⇒ nothing lost. |

**UNWRITABLE rows: none.** The near-miss I hunted hardest for and the honest statement of what *is* lost: the program "band on a derived value with **no stated out-of-band policy**" is unwritable under pure prove-or-reject. That is not a computation — it is the *implicit-refusal default policy*, i.e. exactly the governed-at-runtime disposition (off the table per the brief). Under this posture the author must always pick explicitly among refuse (guard + reject row), saturate (clamp), or constrain the source. That reframes Q2's answer into Q1's question: the loss is a *posture default*, not expressiveness.

## 4. The Q1 link — remediation ≡ provability restoration, by construction

Yes, exactly. The obligation mechanism is defined as "names what would make the operation provably safe" and discharges on carried constraints (`:266`); therefore the reject's demanded remediation set (bound / guard / rule / statically-safe value) *is* the discharge set — supplying it restores provability definitionally, not coincidentally. For the nonlinear rows specifically, the write-site guard restates the checked predicate verbatim, which congruence discharges with zero arithmetic — the annotation *is* the proof. Two honest costs remain: **(a) wrong-reason rejections** — a source-directed obligation ("bound Floor") when the natural fix is elsewhere (`bounds-only…:87-88`, F3a) — a diagnostic-quality burden, not an expressiveness one; **(b) fragment-boundary brittleness** — an ordinary edit can silently cross the provable boundary and flip a compile to reject (`niche-packet:117`) — a real friction/predictability cost of the posture, orthogonal to capability.

## 5. The decidability-ceiling answer (the owner's question, directly)

**Can the engine be made comprehensive enough to prove these? No — two hard walls, and no engineering closes them:** (i) nonlinear integer entailment is undecidable for *any* system, SMT included (Matiyasevich 1970; the project's own "undecidable for ANY compile-time system" at `niche-packet:90-92` is the same wall for intent); (ii) the decidable-but-heavy fragments (nonlinear reals via CAD; arguably large linear systems) are foreclosed by the legible-witness principle (`precept-language-spec.md:225`) — with the noted interpretive fork on whether certificate-producing linear procedures (Fourier–Motzkin) fall inside or outside "no solver." That fork is an owner decision worth making explicitly, because it moves row 4 between "native proof" and "annotation required."

**But comprehensiveness is the wrong ceiling to measure.** Because the language is loop-free, pure, and finite (`:158-174`), every safety fact a derived write could ever need is *expressible in the language itself* as a guard or rule over current fields and args — and congruence discharge of author-stated facts is decidable, terminating, and maximally legible. So the fragment ⟨interval/relational arithmetic + author-stated invariants⟩ is **closed under forcing**: for every true-but-unprovable containment there exists a finite annotation after which the same computation compiles. Undecidability caps what the engine can *discover*; it never caps what the author can *state*. Precept's design already made the one move that matters — banning the constructs (loops, recursion, joins) that make forcing impossible in general-purpose verifiers.

**Bottom line for the posture test:** pure prove-or-reject costs annotation (real, corpus-quantified: `niche-packet:129` — 8 invented bounds on the flagship rewrite, which still ended 28 lines shorter and fully proved; ~30–50 obligation-driven declarations corpus-wide), costs guard legibility in the worst compositions (a §0.8 audience concern), and removes the implicit-refusal default. It removes **no legitimate computation**. Exceptions register, honestly: the `now()` snapshot-semantics prerequisite (row 7) is unverified in the spec; the FM-legibility fork (row 4) is undecided; and the forceability theorem is design-ceiling reasoning, not a shipped-engine property — at *today's* engine, several FORCEABLE rows reject even after annotation (e.g., generalized congruence is unbuilt), which is implementation debt the posture would need to pay before it is honest in shipped form.
