# Canon corrections and supersession map — reconciling committed canon against the owner want statement

**Status**: Draft analysis - 2026-07-19 (agent-authored; evidence only; rulings remain the owner's)

## What this is

The owner's want statement, [`docs/Working/what-i-want-2026-07-16.md`](../what-i-want-2026-07-16.md), settles the compile-time-proof / runtime-governance boundary. The committed docs corpus predates it and — as the two 2026-07-15 forensic analyses established — asserts both sides of that boundary in different places. This document is the convergence worklist: it sweeps committed canon for every statement that contradicts the want statement, and it classifies every top-level working doc against it.

**Two outputs:**

1. **Canon-correction worklist** (§2) — every sentence in committed canon that asserts a model the want statement rules out, with the exact quote, the want-statement section it contradicts, and the *direction* of correction. No replacement wording is proposed — edits are a later owner-approved pass.
2. **Supersession map** (§4) — every git-tracked top-level doc in `docs/Working/` classified as superseded / live-input / orthogonal, as the worklist for a later owner-approved archive pass. Nothing is moved or edited by this document.

**Ground rules applied.** The want statement is authoritative over the corpus; the corpus is compared against it, never used to overrule it. A doc describing *unbuilt* behavior is not a contradiction — the spec states targets. A contradiction is a sentence asserting a *model* the want statement rules out (a post-mutation constraint sweep as an enforcement point, unproven obligations handed to runtime checks, runtime fault tests, constraint validation on restore, warning severity where the want demands rejection). Statements that are merely silent or incomplete relative to the want are not listed. Everything below was verified against the working tree at HEAD `ed57d7fd` (clean tree); all line numbers are current, not inherited from the forensics.

**Terms used below** (plain definitions, since the corpus's own vocabulary is part of the problem):

- **The sweep** — the runtime behavior canon describes in spec §3A.4: after all mutations execute on a working copy, every applicable constraint is re-evaluated against the completed working copy, and the copy is committed only if all pass. The want statement rules this out: "the runtime does **not** re-evaluate them against the post-mutation configuration" (§ Certificates), and runtime evaluation is scoped to "the declared premises (ingress validation of args and editable fields, guards) … and nothing beyond them" (§ The runtime's role).
- **Runtime fault backstop** — a check the evaluator performs at a fault-prone site (a zero test before a division, a bound re-check on a write) as "defense-in-depth." The want statement rules these out: "fault-prevention checks are omitted at evaluation time. No divide-by-zero tests, no overflow guards, no re-checking of proven bounds on writes — the evaluator just computes" (§ The runtime's role).
- **The fault-gate residue** — canon text that classifies declared-bound containment ("no result outside a declared bound") as a member of the *fault* family. Under the want statement there is one constraint mechanism — "Modifiers are sugar for rules … There is one constraint mechanism underneath" (§ The compiler's promise) — and bound containment is rule preservation, proven by the same induction; faults are a separate, enumerable family that gets "the identical premise-and-certificate treatment" (§ Worked example, `PlanRepayment`).
