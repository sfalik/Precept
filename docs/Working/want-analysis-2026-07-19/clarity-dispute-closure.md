## Part 1 — Dispute-closure test

Terms used throughout, defined once: the **third arm** is a hypothesized runtime enforcement point that re-checks whole-entity constraints against the post-mutation working copy at commit ("the sweep"), distinct from compile-time proof (arm 1) and ingress validation of raw external values (arm 2). The **fault gate** is the reading that prove-or-reject applies only at "fault-prone operations" (divisions, accesses) rather than to every declared rule. **Ingress** is the want doc's term for the exactly-two entry points where external data is validated: event args (including construction) and editable-field writes (`what-i-want-2026-07-16.md:129`).

**F12(a), the one genuine new ambiguity found in this pass — per-write vs per-plan.** The want doc supports two readings of what the inductive obligation quantifies over in a multi-write handler (`set A = …` then `set B = …` in one handler):

Two readers will disagree; the canonical doc must pick. **Finding (high).**

### Assessment

Distill the want into the canonical doc, execute the deletions in the same pass, add the enumerations in "what the canonical doc must add," and the yardstick works — with the two-yardstick protocol from Part 3, since surface cells were never the want's to adjudicate.
