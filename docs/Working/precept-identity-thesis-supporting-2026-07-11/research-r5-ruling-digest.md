## 1. What the Hybrid model claims

Frank's ruling states three models were considered (`proof-engine-boundary-ruling-2026-07-06.md:77-81`):

- **Model A** (bounded + defer) — partial compiler, unprovable faults deferred to a runtime fault-trap.
- **Model B** (total + limited surface) — total compiler, undecidable-but-legitimate constructs are inexpressible (author must rewrite).
- **Hybrid (the ruled model)** — "total over the fault surface — no fault deferred" while "admitted as a governed constraint... a fault-prone operation it feeds is still prove-or-reject."

The central claim (`:83-89`): both stated philosophy voices — the "precise" voice (`philosophy.md:57`, "no unproven evaluation faults... no structural dead ends") and the "absolutist" voice (`philosophy.md:49`, "these configurations and workflows cannot exist") — are simultaneously literally true only under Hybrid: every fault over a *derived* value is proven (making `:57` exact), while governance discards invalid external input pre-persist (making `:49` true "by prevention").

## 2. The prove-vs-govern boundary — the "derivation line"

Called the **Obligation-Role Rule** (`:121-140`). Its claim: disposition attaches to an *obligation*, not to a construct's spelling (modifier vs. rule). Two obligation families:

- **Family A (every declared constraint, modifier or rule alike)** generates, always: (1) a **governance** obligation — enforced at runtime on a **raw external value** at its own ingress slot, discarded if it fails (cites `precept-language-spec.md:268`, quoted as "before any computation derives from it"); and (2) a **premise** contribution to the compile-time proof engine, to the extent decidable (`:203`, `:1138`).
- **Family B (every fault-prone operation over a definition-*derived* value)** carries one obligation: compile-time **prove-or-reject** (`:266`) — with **one exception, representational overflow** (see §3 below). Family B ranges over: division, `sqrt`/`pow` non-negativity, empty-collection/index access, and containment of a computed result within a declared `min`/`max` (`OutOfRange`/assignment-range, `:208`).

The one-line boundary as stated (`:134`): *"a raw external value at its own ingress slot is governed; any value a Precept expression has derived from it is proven-or-rejected... decidability decides whether a prove-or-reject obligation discharges or the definition is rejected — never whether it is proven or governed."*

**Decidability's role** is explicitly stated to be the *discharge oracle*, not the *router* (`:130-132`): "Routing by effort would make every newly-hard case a deferral candidate (Model A's slide)... routing by origin cannot slide." This is presented as the correction to a prior draft (v1), which is said to have wrongly declared decidability "irrelevant to routing" (`:119`, `:39`).

## 3. Numeric overflow (the D1 park)

Representational overflow (`NumericOverflow`, a computed value exceeding the *type's* representable range, `Diagnostics.cs:690`) is carved out of the live family-B set and classified as **owner-parked** (D1) — "a disclosed, defense-in-depth known-fault backstop with no live compile-time guarantee... temporary, and no doc may claim it prevented" (`:1`, `:25`, `:130`). This is explicitly distinguished from `OutOfRange` (value-vs-declared-bound), which stays live (`:130`, citing `overflow-prevention-design-analysis.md:516`: "`OutOfRange` remains a separate concern for non-arithmetic bound violations").

D1 itself originates in `compiler-readiness-plan-2026-06-16.md:188-201` (GATE-A resolved "park"): "decimal-representability overflow is an accepted, documented, TEMPORARY known fault... never claim it prevented." Rationale given there: it "was the single largest Phase-3 build... gated on an undecided number model" (`:194`); alternatives rejected were building full obligation-driven bounds-checking or arbitrary-precision numerics, both requiring a number-model redesign not yet made (`:195`). Tradeoff stated explicitly as owner-gated for `philosophy.md` (`:197`).

**The resulting tension, disclosed not resolved:** three canonical, owner-gated sentences still list overflow among prevented faults — `philosophy.md:53` ("arithmetic overflow... compile-time impossibilities"), spec Principle 10 (`:110`), and spec Principle 11 (`:112`) (`proof-engine-boundary-ruling-2026-07-06.md:269-273`). The ruling's R6 recommends surfacing this gap to the owner without editing philosophy or spec text itself (`:268-279`), citing D1's "surfaced-only (DoD-9)" disposition (`decision-index.md:19`, cited but not independently read in this pass).

## 4. The false-security concern and Q9's answer

The trigger question, quoted from the owner in `band-guarantee-boundary-analysis-2026-07-03.md:13`: *"Why check some cases and not others at compile time? That gives a false sense of security. So then we decide it's better to over-reject, and next thing you know we're back to trying to prove everything at compile time."* This is framed as a three-pole trap: **PROVE-EVERYTHING** (over-rejection), **PROVE-NOTHING** (abandons prevention), **PROVE-SOME** (the current/proposed shape — false security → pressure to catch more → slide back to PROVE-EVERYTHING) (`:15-21`).

That analysis's finding (stated as a finding, not a recommendation): **"the circle dissolves — but only under a specific, ownable move"** (`:29`) — redefining the boundary axis from *effort* to *consequence/decidability*, and (critically, stated as a load-bearing precondition, `:58-62`) **only if the runtime governance layer that catches deferred cases actually exists and is total** — "Until that sweep exists, a downgraded bound... is enforced by neither layer... the owner's false-security worry is literally correct as a build fact, not merely a conceptual risk." The document's closing "sharpest finding" restates this as an **empirical, not conceptual, test**: "does the runtime refuse a violating write today? If yes, no hole. If no, the deferred bounds are already unproven-and-ungoverned" (`:199`).

Frank's ruling answers **Q9** (`proof-engine-boundary-ruling-2026-07-06.md:196-199`) by proposing a **per-obligation PROVEN/GOVERNED disposition surface** on `precept_proofs` (MCP) + LS hover, with the explicit rule "**No 'DEFERRED' state** — Hybrid contains no deferred-internal bucket; a 'deferred' entry would be a false category." It further refines this to be *per-obligation, not per-constraint*, since one constraint (e.g. `max 100`) can appear as GOVERNED on its own field's ingress *and* as a PROVEN carrier discharging a different derived-value obligation (`:199`).

Note: Frank's Q9 answer addresses the *legibility* half of the false-security concern (make the boundary visible) but the digest surfaces that the band-guarantee-boundary-analysis's **empirical precondition** — whether the runtime governance sweep actually exists — is a separate, unresolved question the ruling does not claim to have verified; it is captured as a Phase-5/build item (`:324-334`), not as answered.

## 5. Q5, Q7, Q11 (as specifically requested)

- **Q5** (proven-violation severity, `:174-179`): reject as Error, for *declared-bound containment* specifically (not overflow, which is parked). Rejects "warn-and-govern" as an alternative because a warning is a clean compile that would let a known fault compile clean, and because (per the Obligation-Role Rule) there is no "band" category distinct from a rule to warn-and-govern with (`ConstraintKind.cs` has no band member).
- **Q7** (merely-unprovable case, `:184-190`): reject (Error), naming the carrier — for the **live-enforced** set only; representational overflow is exempt (disclosed gap, not a named-carrier rejection). Grounded in `philosophy.md:57` ("no unproven evaluation faults") and the owner-shipped count-bound precedent (`c27a382b`). Notes one honest exit: this verdict could move only if the owner authorizes an explicit author-visible trust construct (R4, not decided in this doc).
- **Q11** (taxonomy, `:201-213`): three diagnostic categories — **Fault floor** (Error, prove-or-reject: DivisionByZero, SqrtOfNegative, OutOfRange, LengthBoundViolation, CountBoundViolation, empty/index access), **Definition incoherence** (Error: RequiredFieldsNeedInitialEvent, UnsatisfiableInitialState, DefaultViolatesRule, provably-always-violating assignment, unreachable state, dead-end), **Flag layer** (Warning: UnsatisfiableGuard, VacuousRule, ContradictoryRule, TautologicalGuard) — **plus a fifth, non-diagnostic row**: the parked overflow lane (backstop only, no live guarantee) and the ingress-governance disposition (a runtime obligation surfaced via Q9, not a diagnostic).

## 6. What Hybrid rejects, and why

- **Model A rejected** "on the principles, independent of the 'no deferral' clause" (`:93-99`): grounded in `philosophy.md:57` and Principle 11 (`precept-language-spec.md:112`, "defensive redundancy, never... the primary enforcement mechanism"). Three corroborations offered: the owner-shipped count-bound "Reading A" precedent (`c27a382b`); the bug tracker classifying silent-deferral-shaped behaviors as bugs (BUG-017/020/021, `bugs.md:171/188/203`); and an adversarial red-team's conclusion that Model A "fails specifically against Precept's non-negotiable `philosophy.md` [line 57]" (`verify-1-redteam-modelA.md`, cited but not independently read in this pass).
- **Pure Model B rejected** on expressiveness (`:101-103`): would refuse genuinely nonlinear governance rules (balance identities, ratios, product rules), citing "21 of 77 sample `.precept` files contain product expressions" (a grep re-confirmed in the doc's own text) and a prior corpus audit claiming "~89% of invariants in-fragment" (`precept-guarantee-specification-2026-06-05.md` §7, cited via a third document `verify-2`, not independently read in this pass).

## 7. The D2 philosophy-alignment analysis — a genuinely unresolved tension carried alongside

`d2-proven-violation-philosophy-analysis-2026-07-03.md` is an earlier, narrower analysis (predates Frank's Rev 3) asking whether D2's "proven-violation warning" for non-safety bounds aligns with "prevention, not detection." It explicitly surfaces **both sides without resolving them** (§3a "ALIGNS" vs §3b "does NOT align", `:57-82`):

- *For alignment:* bands are outside `philosophy.md:53`'s enumerated impossibilities; governance is atomic/unbypassable (`:35`); a provably-dead structural case (`UnsatisfiableGuard`) is *already* a warning at HEAD (`Diagnostics.cs:770`), so a proven-violation band-as-warning is "consistent with existing treatment, not an anomaly" (`:67`) — **flagged**: this is an explicit "HEAD already does X elsewhere" argument used as a philosophical-consistency corroboration, not a philosophy/identity argument on its own terms.
- *Against alignment:* `philosophy.md:43` ("invalid configurations are structurally impossible") and `:49` ("no operation can produce a result that violates a declared rule") read directly against a warning-and-compile-clean disposition; and two internal inconsistencies are named — (1) a default that provably violates its bound is Error, but a set-action that provably violates the same bound is Warning, with only a "when" (creation vs. transition) distinguishing them (`:77`); (2) the plan's own cross-transition-ensure reasoning calls a provably-unsatisfiable ensure "genuine prove-or-reject territory... a complete runtime cannot rescue" it (`:1097`/`:1423` of the readiness plan), yet a set-action band violated for *all* inputs is routed to a warning — "the plan applies opposite dispositions to the same structural shape" (`:79`).

This document explicitly declines to adjudicate ("does not recommend option 1, 2, 3, or 4", `:101`) and states the crux as four neutrally-framed open questions (`:85-93`), the sharpest being: is a provably-violated bound a `philosophy.md:43` "invalid configuration," or a `philosophy.md:35/:55` governance concern — and does the answer change while the runtime governance sweep (which the "relocation, not weakening" argument depends on) remains unbuilt.

**Note on relationship to Frank's later ruling**: Frank's Rev 3 states it "settles D2 by declining it and by dissolving its premise" via the constraint=rule correction (`proof-engine-boundary-ruling-2026-07-06.md:289`), and separately resolves Q5 (declared-bound containment stays Error, not warning — `:175`) in a way that appears to land on the *opposite* side from D2's original warning-based band reclassification described in the compiler-readiness-plan. Whether Frank's ruling and the D2 doc's open tension have actually been reconciled (vs. simply superseded by assertion) is not verifiable from these documents alone — the ruling's own supersession list (`:295-303`) claims to decline D2 as "an unratified proposal," but the D2 analysis document is not listed among files whose open questions were answered.

## 9. Explicit flags — claims resting on "HEAD/shipped-code already does this" rather than a philosophy/identity argument

Per the instruction to flag every status-quo-as-justification move:

2. **Boundary ruling Leg 3 precedent**: "Precept's shipped code is already this shape... The running compiler is nowhere Model A by design" (`:106`) — offered as one of several "Leg 3 / precedent" supports for the model choice.
3. **D2 analysis §3a**: "a provably-dead structural case is **already** a warning in shipped canon (`UnsatisfiableGuard`)... a proven-violation band as a warning is **consistent with existing treatment, not an anomaly**" (`d2-proven-violation-philosophy-analysis-2026-07-03.md:67`) — an explicit status-quo-consistency argument used to support D2's philosophical alignment, presented alongside (not instead of) the countervailing philosophy-text argument in §3b.
4. **Band-guarantee-boundary-analysis §2**: "Precept **already runs** this architecture... via carries-proof" (`band-guarantee-boundary-analysis-2026-07-03.md:44-46`) and "Precept **already commits** to this honesty standard — for approximation (`philosophy.md:25`)... the bounds question is the same shape" (`:83`) — both extend an existing mechanism's precedent by analogy to justify the new case; the analogy itself is not defended independently of the existing implementation.
5. **Boundary ruling §9 provenance note, point 3**: "under Challenge 1 [D2's] central category... **does not exist** — a bound is a rule; `ConstraintKind.cs` has no band member" (`:289`) — a code-shape fact (`ConstraintKind.cs:10`) used to dissolve a design proposal's premise, flagged in the document itself as something v1 had wrongly treated as a *routing* defeater rather than acknowledging it as evidence of what would need to be *built* were Model A chosen (the doc's own honesty caveat at `:99`: "the missing runtime surface is A's price... not A's defeater").

None of these five are presented as the *sole* basis for their respective conclusions in the source documents — each is paired with at least one philosophy-text citation (`philosophy.md:57`, `:49`, `:55`, `:43`) — but each does independent argumentative work alongside the philosophy citations, and a reader who discounted the archaeological leg would be left with a narrower case in each instance.
