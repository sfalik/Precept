## 0. The boundary (read first)

This plan finishes **the compiler**. It deliberately stops at a hard line.

- **IN SCOPE — (a) compiler code.** Every lexer / parser / type-checker / binder / graph-analyzer / proof-engine / diagnostic-emission / registry / Roslyn-analyzer change. Verifiable at compile time via `precept_compile` / `dotnet build`. The runtime being a stub never blocks a compiler exit criterion.
- **IN SCOPE — (b) all canonical design/doc work.** Compiler canon (`docs/compiler/*`, `docs/language/*`) **and** runtime canon (`docs/runtime/*.md`). Wherever a compiler decision forces a runtime contract (fault delivery, governance sweep, conversion semantics), that contract's **design is captured here** so the eventual runtime build inherits a complete spec. Nothing is lost.
- **OUT OF SCOPE — runtime coding.** The executable model, the governance/constraint sweep, Fire / Update / InspectFire / InspectUpdate / Restore, ingress enforcement, value-application. **Verified stub:** `src/Precept/Runtime/Evaluator.cs` — Fire (`:80`), Update (`:99`), InspectFire (`:121`), InspectUpdate (`:132`), Restore (`:155`) all `throw new NotImplementedException()`, each tagged "once the executable model is designed." There is no constraint sweep, no governance lane, and the executable model is not even designed. Every item whose **correctness / exit-criterion requires the runtime to execute** is deferred — see § 11 Runtime-Coding Handoff.

### Three boundary disciplines (apply to every item)

1. **Compiler-completable exit criteria.** No exit criterion in this plan asserts a runtime-execution outcome. A band slice's exit is "compiles clean / emits the proven-violation warning," never "governance refuses the write."
2. **Mandatory capture obligation per defer.** Every `RUNTIME_CODE_DEFER` item names the `docs/runtime/*.md` it must revise so the deferred coding has a spec. A defer with no capture pointer is a silent loss and is disallowed.
3. **Prove-or-reject (permanent) and admit-now / defer-enforcement (transient).** The compiler rejects what it cannot prove **fault-safe** — period. This is permanent prevention-engine behavior and has nothing to do with whether the runtime exists; runtime-absence is **not** fault-unprovability, so a not-yet-built runtime never converts a fault-safe operation into a rejection ground. Separately, where an operation **is** fault-safe once the runtime performs it (e.g. reclassified-band governance — the canonical model; D8 dimension-narrowed conversion; committed-state tier-2 discharge), the compiler **admits** it now and the runtime **enforcement** is deferred and captured in § 11 — exactly the treatment reclassified bands (D2/D3) already get. The compiler does **not** keep rejecting merely because the runtime is unbuilt; pre-release (no users, `Evaluator.cs` all `NotImplementedException`) a transient enforcement gap creates no live fault (D3). The capture obligation (discipline 2) — not a held compiler rejection — is what keeps the deferred enforcement honest.

**Definition of Done (redefined):** *compiler finished; runtime design fully captured in runtime canon; runtime coding handed off as an enumerated separate initiative.* See § 12.

## 2. Decisions captured (apply — do not re-litigate)

Four owner decisions made this session reshape the prior plan. They are applied throughout; the per-phase rows assume them.

### D1 — OVERFLOW PARKED (GATE-A resolves as "park")

Decimal-representability overflow is an **accepted, documented, TEMPORARY known fault.** We do **not** build the representability-overflow obligation/family; **no** bounds-checking, **no** multi-field magnitude proof; the number-model redesign is parked. **Document overflow as a known limitation; never claim it prevented.** Temporal-arithmetic overflow is the same representability genus and parks with it. The maxplaces compile-time precision proof is the same number-model class and parks too.

- **Rationale:** the representability family was the single largest Phase-3 build and the only floor item gated on an undecided number model; parking it collapses that risk and lets the rest of the floor ship now.
- **Alternatives rejected:** (a) build fixed-decimal + obligation-driven bounds + prove-or-reject representability — too large, gated on an unmade number-model decision; (b) arbitrary-precision numerics — a number-model redesign, parked.
- **Precedent:** `fault-floor-definition-2026-06-11.md` named GATE-A the highest-leverage relief valve; owner closed it as park.
- **Tradeoff accepted:** the floor is **prove-or-reject EXCEPT** decimal/temporal representability overflow — a documented known fault never claimed prevented. This is an **honesty-about-approximation** carve-out, not a relocation (contrast D2). It is **owner-gated for `philosophy.md`** — surface, do not auto-edit.

**Consequence on the registry (Phase 1):** the NumericOverflow RETARGET no longer points at a built obligation. Keep `FaultCode.NumericOverflow` as a documented defense-in-depth known-fault trap with **no** live `[StaticallyPreventable]` guarantee behind it; its `[StaticallyPreventable]` partner is an honest **gap**. Do **not** add `FaultCode.TemporalOverflow`. The PRE0078 message split (so "exceeded the representable range" stops attaching to a band check) still proceeds — compiler-pure and unrelated to the parked obligation.

**Compiler self-protection carve-out (NOT parked):** the compiler's own checked constant-fold (so a `2e28 * 2e28` literal cannot crash the pipeline) is compiler robustness, distinct from the parked runtime representability obligation. Stays COMPILER_CODE (Phase 4); verify whether the compiler folds such literals at all before scoping.

### D2 — BAND RIGHT-SIZING SPLITS (compiler half in scope; enforcement deferred)

The band-containment scale-back splits cleanly:

- **Compiler half (IN SCOPE, Phase 1):** reclassify `OutOfRange` / `LengthBound` / `CountBound` + the PRE0078-band check from fault/prove-or-reject to a **compile-time flag/warning** (proven-violation only), trim the registry, amend the spec. This only **stops the compiler falsely rejecting valid precepts** — no runtime needed.
- **Runtime half (DEFER):** the governance sweep that **enforces** the reclassified bounds at commit/ingress, plus the discharging constraints that make committed-state tier-2 discharge sound. Design captured in runtime canon (§ 11).

- **Rationale:** the band lane was over-reach (rejecting merely-unprovable intervals); downgrading to a proven-violation flag removes false rejections without losing genuine prevention.
- **Alternatives rejected:** keep prove-or-reject on bands (over-rejects valid precepts); delete bands entirely (loses the genuine proven-violation signal).
- **Precedent:** `fault-floor-definition-2026-06-11.md` scale-backs SB-01..SB-08.
- **Tradeoff accepted:** **prevention is relocated, not weakened** (Frank A6) — for non-proof-carrying / ingress values, runtime governance refusal is still atomic prevention. `philosophy.md` L53's enumerated impossibilities (divisor, overflow, empty-collection) are all **retained** floor families; bands are not in that list. **Carve-out preserved:** the carries-proof set stays in the floor — mincount `count>0` (Strategy-2 access-safety arm), sign-modifier / rule-fact preservation. With overflow parked (D1), the "bounds consumed by representability proofs" carries-proof reason **evaporates**, so the non-proof-carrying exit is cleaner (no representability reinstatement to hedge). **Keep distinct from D1:** bands relocate; overflow is genuinely relaxed (a disclosed limitation).

### D3 — ATOMICITY RELAXED

Pre-release, **no users**, stubbed runtime → transient gaps are harmless. **Drop** the "atomic coordinated move so bounds are never enforced nowhere" machinery (it protects a running product we do not have). The "Slice-wiring-before-band-retirement" hard coupling is **removed** — with the runtime stubbed, bounds are enforced nowhere regardless, so the window is moot.

**KEEP exactly one internal-correctness ordering:** the fault registry must be **honest BEFORE** the Phase-2 position-totality checker reads it. Prefer simple incremental sequencing over all-or-nothing merges everywhere else.

- **Rationale:** atomicity machinery exists to protect a live deployment; there isn't one.
- **Alternatives rejected:** keep the coordinated merge (couples a compiler change to a deferred runtime change that cannot land at all — would block the compiler half indefinitely).
- **Precedent:** MEMORY project note (solo-dev / pre-release / runtime-still-stub).
- **Tradeoff accepted:** a transient compile window where reclassified bands are enforced nowhere — harmless with no users and no runtime.

### Stress 4 — Does any RETAINED slice assert a runtime-EXECUTION exit criterion, and is every admitted fault-safe-but-runtime-dependent operation's enforcement captured in § 11? (no-silent-loss hunt)

This is the most important probe for the boundary. Under the prove-or-reject / admit-now-defer-enforcement split (§0 discipline 3), **admitting a fault-safe operation whose enforcement defers is the correct pre-release behavior**, not a leak — the runtime is a pure stub, nothing executes, so an admitted-but-unenforced obligation creates no live fault (D3) as long as its enforcement is captured in § 11. The genuine risks are: (a) a retained exit criterion that asserts a runtime-**execution** outcome (a disguised boundary violation), or (b) an admitted fault-safe operation whose deferred enforcement is **not** captured with a pointer (a silent loss). Walking the slices that touch a runtime-adjacent surface:

- **Band reclassification (Phase 1 Slice 1.3).** Exit: out-of-band write on a non-proof-carrying field *compiles clean*; a *provable* band violation *emits the proven-violation warning*; carries-proof set still *rejects*. All three are `precept_compile` / `dotnet build` outcomes. The slice never asserts "governance refuses the write" — that is the deferred enforcement half, captured in `evaluator.md §7.6`. **No leak.** This is the admit-now model: the compiler admits the fault-safe operation, and admitting a merely-unprovable interval at compile time does not create a guaranteed fault — it defers a governance decision the runtime owns.

- **D8 dimension-narrowed / commensurable cross-unit assignment (Phase 4).** The *static-fold subset* (both operands compile-time constant) is compiler-pure. The *dynamic-write case* is **also fault-safe**: target-directed conversion of a commensurable same-dimension quantity multiplies by a finite UCUM scale factor — a total operation with no fault genus a complete runtime could not perform (the only overflow genus is the PARKED representability family, D1, never a rejection ground anywhere — not a D8-specific waiver). A fully-built runtime performs the conversion, so the compiler **admits** the dynamic-write case now and the conversion's **enforcement defers** to `evaluator.md §Intake-Boundary` — the same admit-now / defer-enforcement treatment bands get. **No leak** — the admission creates no live fault pre-release (runtime stubbed), and the deferred enforcement carries a § 11 capture pointer (verify the pointer exists — no silent loss). A deepening pass must keep the enforcement captured, not re-introduce a held compiler over-rejection.

- **2c-ii field-reference bound enforcement (Phase 5).** Exit (Frank-flagged): assert **prove-or-reject at compile time** via `Compiler.Compile` — *never* "a running entity's out-of-bound write is refused." The runtime ingress enforcement is the deferred tail (`evaluator.md §7.6`). **No leak** — the exit is a compile-time discharge verdict; the unconsumed-artifact guard (Stress 3a) additionally ensures the synthesized rule is either consumed at compile time or co-deferred.

- **Write-aware tier-2 discharge (Phase 3 Slice 3.1).** The slice's genuine compiler work is **intra-chain (same-transaction)** write-awareness: a stale intra-chain discharge is real fault-unprovability (the compiler can SEE the prefix writes), so the compiler **rejects** — permanent prove-or-reject, no exit criterion asserts a runtime outcome.
