## Findings

### F1 — A pair of behaviors at two sample points is a test, not a definition (blocking-the-premise)

**Claim.** Line 20 asserts "this pair *is* the definition of the cell." It is not, and cannot be: the pair fixes compiler behavior at exactly two programs (base; base+listed-addition) and says nothing about the unbounded space between them. Two compilers can satisfy every cell's pair and differ observably on the proof surface.

**Evidence.** Base A (lines 52–69). The two listed additions are the verbatim-WP guard and the `250/750` arg-bound split. Now take Base A + `when Add.Amount1 <= 500 and Add.Amount2 <= 500` — a guard that *implies* the WP but is not it, and is not either listed addition. Compiler 1 (interval propagation through guard conjuncts) discharges; Compiler 2 (verbatim guard-match only) rejects. Both satisfy every cell in the doc. The matrix, read as the definition, is silent on which is correct — yet this is precisely the kind of question ("how strong is discharge?") a definition of the proof surface exists to answer. The real discharge contract is strategy-relative — "anything the strategy set can derive from the declared premises" — and the strategy semantics live outside the matrix (line 32 points at the `ProofStrategy` enum and a working-doc taxonomy, neither of which the matrix defines). The doc's own second-use framing (line 10: "every defined cell converts mechanically into a reject/discharge test pair") is the tell: the cell shape is natively a test shape, and a finite test suite underdetermines semantics.

**Amendment (smallest).** Reframe what a cell *is*: a cell = (obligation **schema** with metavariables, per-premise-class **discharge contract** stated as "any addition whose premise instantiates class P such that strategy S derives the WP discharges," suggestion **schema** — see F3). The concrete base/addition pair the doc currently calls the definition becomes the cell's **witness** — the canonical instance used for the test pair and for the diagnostic's example text. The pair stays; its claimed status changes from "is the definition" to "witnesses the definition." This one reframing dissolves most of the downstream findings' force.

### F2 — The equivalence-class judgment is circular, and it is the load-bearing joint of the exhaustiveness claim (blocking-the-premise)

**Claim.** Line 125: a 2-field rule "represents the n-field case wherever arity does not change the derivation — a per-family judgment." But *the derivation is the thing being defined*. Whether arity changes the derivation is a fact about the compiler's strategy semantics, which don't exist yet — the matrix is supposed to be producing them. So the quotient that makes the enumeration finite is defined in terms of the enumeration's output. Two compilers can partition programs into cells differently — each with a recorded "per-family judgment" — and both claim every-cell conformance while disagreeing on which cell a real program falls into. The exhaustiveness claim (line 127: "exhaustively documented when every non-empty cell of the pruned matrix carries a disposition") inherits this circularity: "exhaustive over classes I chose" is not a mechanical completeness property; it is the same vagueness the matrix exists to remove, relocated into the class boundaries.

**Evidence.** Line 125 (the quoted judgment); contrast with the *derived* pruning on the same line ("overwrite excludes premise (d) structurally"), which IS well-defined because it follows from write-structure syntax, not from derivation behavior.

**Amendment (smallest).** Define equivalence classes **by obligation/WP schema, not by derivation**: two programs are in one cell iff their minted obligations unify with the same schema under a stated normalization (see F4) with only metavariable instantiation differing. That is checkable from the program text without running the prover. The "per-family judgment... recorded, not assumed" sentence then becomes unnecessary — the class boundary is syntactic, and where arity genuinely changes the *schema* (e.g., a fact-chaining shape appears), it lands in a different cell by construction. This is the difference between "exhaustive by definition of the quotient" and "exhaustive by my judgment, which I wrote down."

### F3 — The anti-drift device "the suggestion IS the addition in the next row" is already false inside the doc's own worked slice (weakens)

**Claim.** Line 22 makes the identity "the suggestion the definition requires *is* the addition in the next row, so suggestion and fix cannot drift apart" the cell's mechanism for defining the diagnostic. Base A breaks it twice: (i) there are **two** next rows — which is "the" suggestion? The expected-rejection text (line 62: "bound the args or guard the sum") quietly answers "the disjunction of premise *classes*," which contradicts the row-identity; (ii) row 2's addition is `Amount1 max 250, Amount2 max 750` — an arbitrary split of 1000 with no principled basis. No compiler should suggest those constants verbatim, and if it must not, then the suggestion is *not* the addition in the row, and the anti-drift identity fails exactly where a cell has parameterized or multiple additions — i.e., in most non-trivial cells. Note Base C (line 103) keeps the identity only because its addition is the unique verbatim-WP guard.

**Evidence.** Lines 22, 62, 64–67 vs. line 103.

**Amendment (smallest).** Define the required suggestion **per premise class, as a schema**: "add a guard equivalent to the WP `⟨WP⟩`" / "bound the args such that the interval sum satisfies `⟨WP⟩`." When multiple premise classes can discharge, the diagnostic must name **all applicable classes** (this is checkable: the class set is derivable from the cell's write-structure pruning — the doc's own Base A/B/C contrast at line 109 shows the candidate-class set is a per-cell fact). Row additions become instantiation witnesses of the schemas. Drift-resistance survives in a weaker but honest form: the suggestion schema and the addition rows are both generated from the same premise-class column.

### F4 — "Guard fact = the WP verbatim" makes the definition syntax-sensitive with no stated normalization (weakens)

**Claim.** Lines 66 and 107 define §1a guard-match discharge as the guard being "the WP verbatim." Is `1000 >= Amount1 + Amount2` a match? `Amount2 + Amount1 <= 1000`? A WP has one meaning and unboundedly many spellings; "verbatim" without a normalization rule means two conforming compilers differ on trivially-rearranged guards — a lens-1 divergence sitting in the doc's own strategy column.

**Amendment (smallest).** One sentence in Vocabulary: guard-match is defined up to a stated normal form (e.g., the compiler's canonical comparison normalization — cite the actual normalizer or define ordering/commutation rules), and the word "verbatim" is replaced with "normal-form-equal."

### F5 — The disposition trichotomy is violated by the doc itself, and "empty" is not a disposition (weakens)

**Claim.** Line 8 declares the answer set: defined / deferred / open. Line 118 uses a fourth label, "**Structural gap** (Q10)," never defined or mapped into the trichotomy. Separately, line 127 restricts the completeness obligation to "every **non-empty** cell" but never says how a cell is established empty — so empty-by-derivation ("no-write × preservation is vacuous because axiom X") and silently-missing (a cell nobody generated) are indistinguishable on the page. An incorrectly-pruned cell is a silent gap wearing an "empty" badge — precisely the absence-as-answer failure mode the matrix exists to kill. The taxonomy also has no slot for the failure this project just escaped: "defined differently by two canon sources" / "defined but owner-disputed."

**Evidence.** Line 8 vs. line 118; line 125 (pruning is "derived" but the derivation record is not required per pruned cell); line 127.

**Amendment (smallest).** (i) Make **empty** an explicit fourth disposition requiring a one-line derivation citation ("empty: overwrite excludes (d) per axiom …") so pruned cells are written, not absent — the completeness claim then quantifies over ALL cells of the product, which is what makes it mechanical. (ii) Either define "structural gap" as a sub-kind of open (with a required pointer to the missing surface decision) or delete the label and use "open (Q10)." (iii) Add a **conflicted** disposition (two canon sources answer differently — cite both, route to owner); a matrix that cannot *record* the canon-asserts-both-answers state cannot detect its recurrence.

### F6 — Authority is double-claimed and defined cells carry no citations: the drift machinery for canon-asserts-both-answers 2.0 is present (weakens — amendment mandatory)

**Claim.** Line 4: "Authoritative model: … the want doc." Line 131: "the code above is **normative** for the matrix." Two normativity claims, no conflict rule. Worse, every defined cell's content — the WP, the expected-rejection prose, the premise-class assignment — is the matrix author's *derivation from* the want doc, asserted without citation, while the edge cells (lines 117–119) DO carry citations. If one derivation is wrong, the matrix asserts what the want doc doesn't; then line 133 has the canonical doc distilled *from the matrix* ("the matrix supplies the canonical doc's per-cell semantics"), after which three artifacts speak, and forensics (395e677f) has shown where that ends. The doc also never says what the matrix becomes after distillation — line 137 keeps it alive forever as the test basis, i.e., a permanent second restatement.

**Amendment (smallest).** Three sentences in the doc: (i) **Conflict rule**: the want doc wins over the matrix until the canonical doc is ratified; thereafter the canonical doc wins and the matrix is checked against it; the matrix is never independently authoritative — line 131's "normative" is downgraded to "normative *for the test pairs*, derived from the model." (ii) **Citation symmetry**: every defined cell must cite the want-doc sentence(s) its obligation and premise availability derive from, exactly as edge cells already must. (iii) **Lifecycle**: on promotion, the matrix's definitional role ends; it persists only as the derived test basis, regenerated/re-verified against canon.

### F7 — Cells are defined in isolation; the compiler is defined on whole files — and the doc's claimed superiority over the deletion method trades away exactly the composition coverage the deletion method had (weakens)

**Claim.** Line 25 claims the addition framing "is stronger as a definition" than the want doc's deletion method. It is stronger *per cell* (it pins the rejection, the suggestion, and the fix together) but strictly weaker on **composition**: the want doc's deletion table (want doc lines 110–131) mutates a full, realistic file, so every obligation is exercised with all other premises co-present — including the symmetric-write-site obligations (`ReduceLimit` inheriting the Balance rule) that only appear when handlers coexist. The matrix's minimal isolated bases cannot detect interaction defects: an addition that discharges one obligation while breaking another (a new guard creating a dead row; an arg bound shifting another handler's proof), or premise leakage across handlers. Two compilers can agree cell-wise and differ on composed files.

**Amendment (smallest).** State compositionality as an explicit axiom of the model ("obligations are minted and discharged per write site; premises are scoped per handler; no cell's disposition depends on any other cell") — this is a want-doc-level claim and needs its citation — AND keep the deletion method as the composition check: one composed exemplar file per family, deletion pass over it, alongside the per-cell addition pairs. The two methods are complementary; drop the strict-superiority claim in line 25.

### F8 — Base canonicity is unstated (minor)

"The natural authoring state" (line 14) is aesthetic, not canonical: `Amount1 + Amount2` vs `Amount2 + Amount1` vs a three-line equivalent all mint the same obligation. Under the F1 reframing this dissolves (the base is any instance of the schema; the written base is the witness), but the doc should say so — one sentence: the base is a representative of the obligation-schema class under the F4 normalization, and diagnostics that quote source quote the *author's* text, not the representative's.

## What IS sound

- **The triple = certificate shape** (lines 12–18). Aligning matrix rows with the want doc's certificate record (theorem, premises, derivation) so that tests, diagnostics, and certificates speak one vocabulary is genuinely good structure — it is the reuse-not-parallel discipline applied to the definitional artifact itself, and it survives every amendment above unchanged.
- **The derived pruning by write structure** (lines 109, 125): "overwrite excludes premise (d) structurally" is a real, syntactically-checkable theorem about premise availability, and the Base A/B/C contrast (same rule, three WPs, three different viable premise classes) demonstrates the axis does real work. This is the part of the enumeration that is already definition-grade — F2's amendment asks the equivalence classes to be built the same way.
- **The no-silent-cells forcing function** (lines 8, 121, 127). Making "the want doc does not cover X" a written, findable statement rather than an absence is the correct structural response to the canon-asserts-both-answers failure, and it survives as the matrix's core value even after F1 demotes the pairs from definition to witness.
- **The provable-under-want / proven-today separation with ✓v provenance** (lines 42, 66, 87) directly answers the failed 2026-07-14 probe (codes-not-prose, calibrated live compiles at a named HEAD) and refuses to redefine the bar — build status never contaminates model status.
- **The edge-cell discipline** (lines 111–121): dispositions with citations for cells beyond the surface is exactly right — the F5/F6 amendments merely extend that same discipline to empty cells and defined cells.

## Lens 5 — should the ordering invert?

The strongest case for canon-first: a definition must be *generative* — a finite quantified statement determining behavior on unboundedly many programs. Prose canon states the generative rules (obligation minting, WP semantics, premise classes, strategy semantics, suggestion policy); the matrix then *checks* — enumerate cells, verify each pair is derivable from canon, flag underivable cells as gaps. Under matrix-first, generalization from examples happens during distillation, outside the matrix's own verification mechanism — which is exactly where "wherever arity does not change the derivation" hand-waving lives (F2).

But full inversion misreads the situation: the generative statement **already exists** — the want doc's base-case/inductive-step/premise-classes text IS quantified canon (want doc lines 16–27). The matrix is not inducing a model from examples; it is stress-testing an existing generative model cell-by-cell to find its under-determined spots. The right resolution separates **discovery order** (matrix probes → gaps found → canon closes them: keep) from **authority order** (canon defines → matrix checks: fix). Line 133's "the matrix supplies the canonical doc's per-cell semantics" gets the authority direction wrong — the matrix supplies *coverage and worked witnesses*; every cell answer must be derivable from a generative sentence, and a cell whose answer can't be so derived indicates a missing generative sentence to author in canon, never a cell answer to transplant. This is a one-line correction to line 133, and it is the same correction as F6's conflict rule seen from the other side.

## Verdict

**As currently structured — no.** Two findings block the premise: the behavior-pair-as-definition identity (F1) makes the matrix a finite test suite claiming to be a semantics, and the derivation-relative equivalence classes (F2) make its exhaustiveness claim non-mechanical. Left as-is, the matrix would define the compiler at sample points, hand the generalization to an unreviewed distillation step, and stand as a second authoritative restatement — the drift configuration this project just spent two months escaping.

**With the amendments — yes, and cheaply.** None of the fixes discard structure; they retype it: cells become schemas with per-premise-class discharge contracts and suggestion schemas (F1, F3), whose concrete pairs are witnesses; equivalence classes become obligation-schema quotients under a stated normalization (F2, F4); the disposition set becomes defined / deferred / open / empty (+ conflicted), all citation-bearing (F5, F6); authority is one clause — want doc (then canonical doc) defines, matrix checks and witnesses (F6, lens 5); and the deletion method is retained as the composition check beside the addition pairs (F7). Under that shape the matrix is exactly what the owner needs: the exhaustiveness instrument and witness suite that makes every absence a written statement — with the generative semantics living where definitions must live, in the canon the matrix exists to complete.
