### [true-fault] DivisionByZero (FaultCode 1, PRE0083 link; emission via PRE0083/contextual dispatch)

- **Registry:** [StaticallyPreventable(DivisionByZero)]; IN bijective core (StaticallyPreventableMap.cs:30)
- **Reasoning:** Can-it-compute: NO. Principle 10 (spec 0.1) forbids NaN/Infinity, so x/0 has no result; it fires mid-plan during opcode execution (evaluator.md 7.0/7.3) before any constraint verdict exists — the only landing is the Faulted backstop. Prove-or-reject two-tier divisor safety (spec 0.6 item 3) is exactly the floor posture. Floor caveat: the obligation must exist at EVERY expression position — the 10 fail-open positions (guard slots, because-interpolation, default interiors, BUG-032 member-call args) are floor gaps in this lane: a divide inside a guard faults during row dispatch (evaluator.md Step 2a) with no recoverable outcome.
- **Runtime cite:** evaluator.md sec 9: 'Impossible-path fault | EventOutcome.Faulted(fault) | Defense-in-depth backstop'; fault-system.md divide-by-zero end-to-end example; result-types.md:51 faults excluded from outcome hierarchy

### [mixed] QualifierMismatch (FaultCode 11, PRE0068)

- **Registry:** [StaticallyPreventable(QualifierMismatch)]; NOT in bijective core. PRE0068 is DiagnosticStage.Type (Diagnostics.cs:608). Fault message (Faults.cs:34): 'Typed constant qualifier {0} does not match the field's declared qualifier {1}' — an assignment-shape description
- **Reasoning:** Four sub-cases diverge. (a) Incompatible-dimension or cross-currency ARITHMETIC mid-plan (USD+EUR, kg+miles): no defined result exists — genuine can't-compute, true fault; prevention is static qualifier typing (TC) plus proof-stage narrowing for open fields (PRE0141/AssignmentQualifier, UnprovedQualifierCompatibility) — floor. (b) Same-dimension different-unit (kg vs g): NOT a fault — UCUM intake normalization makes it compute (evaluator.md Intake-Boundary Normalization: 'every quantity inside the engine is in UCUM base units'); but BUG-030 (cancellation drops the kg->g x1000 factor, false Proved) is a floor-grade soundness bug in this lane because it silently computes WRONG values under a green ledger. (c) Wrong-qualifier EXTERNAL value entering a declared field: ingress governance refuses recoverably — runtime-api.md:656 explicitly lists qualifiers in ingress governance — rule/governance, not fault; the Faults.cs message describes exactly this sub-case, i.e. the registry encodes the governance sub-case as the fault. (d) Counting units (each vs box): TC-owned (PRE0137), runtime preserves identity by design. Plus the qualifier-source-mutation hole (writes to a {X} base leaving dependent money mislabeled): no fault fires AT ALL — clean wrong success — making the missing static obligation floor-grade (it protects the can't-trust-the-number lane, the flagship currency-safety claim).
- **Mixed split:** Arithmetic on incompatible qualifier atoms = true fault (floor: TC typing + PRE0141 narrowing + qualifier-source obligation; BUG-030 fix). Declared-field ingress/assignment mismatch = governance/rule (recoverable refusal; reclassify out of fault framing — the current Faults.cs message names this sub-case). Counting-unit and closed/static qualifier checks = type-checker-owned.
- **Runtime cite:** runtime-api.md:656 'TypeRuntimeMeta / TypeRuntime enforce a field's declared constraints (qualifiers, bounds) on every externally-sourced value at runtime ingress'; evaluator.md Intake-Boundary Normalization + 'Counting units are not normalized'

### [mixed] NumericOverflow (FaultCode 12, PRE0078)

- **Registry:** [StaticallyPreventable(NumericOverflow)]; IN bijective core. PRE0078 message: 'Numeric computation exceeded the representable range on field {0}' — but the obligation that emits it (IntervalContainment, ProofRequirement.cs:343-346) checks DECLARED min/max bounds, and is only created when declared bounds exist (Actions.cs:295 'if (min.HasValue || max.HasValue)')
- **Reasoning:** THE load-bearing split, and the engine currently has it inverted. Sub-case A — type REPRESENTABILITY overflow (decimal/long range, incl. UCUM factor application): genuinely can't compute — .NET decimal arithmetic throws mid-plan, before any constraint verdict; only the Faulted trap exists. TRUE FAULT, floor — and it is currently UNPROVEN ANYWHERE: no representability obligation exists (verified: obligation creation is gated on declared bounds; established probe 2e9x2e9 compiles clean). This is the floor gap. Sub-case B — DECLARED-band containment (what PRE0078 actually enforces): bounds are rule sugar (spec 2.4: 'min 5 and rule X >= 5 are interchangeable to the proof engine'); a computed value outside the band computes fine and the post-mutation sweep refuses recoverably (ConstraintsFailed, working-copy discard, evaluator.md Step 2e + spec 3A.4). RULE-MISCLASSIFIED. Verified live this session: 'field Amount as number max 100' + 'set Amount = Other + 200' draws PRE0078 ERROR on a merely-UNKNOWN interval ([-inf..+inf] — reject-on-unprovable, not proven-violation), while the spec-identical 'rule Amount <= 100' twin compiles CLEAN with zero obligations. Same business constraint, two syntaxes, opposite guarantee — the twin-syntax inconsistency, live in the band lane. Consequence: BUG-017/BUG-021 (band-direction obligation creation holes) stop being floor bugs under reclassification; the owed floor work is the representability obligation that does not exist.
- **Mixed split:** Representability overflow = true fault, floor, currently a GAP (no obligation; build it — obligation-driven bounds demand per the niche packet's bounds-invention mitigation). Declared-band containment = rule preservation; runtime consequence is ConstraintsFailed via sweep; scale back PRE0078's prove-or-reject to governance + flag-sound warning (or align with the rule twin), and rename/split the diagnostic so the message stops claiming representability.
- **Runtime cite:** evaluator.md Working Copy step 7 'if constraints fail, return the array to ArrayPool' + sec 7.6 EvaluateConstraint -> ConstraintViolation -> ConstraintsFailed; spec 3A.4 mutation atomicity; live probes this session (BandProbeModifier PRE0078 error vs BandProbeRule clean)

### [rule-misclassified-as-fault] OutOfRange (FaultCode 13, PRE0079)

- **Registry:** [StaticallyPreventable(OutOfRange)]; NOT in bijective core (the map already treats it as non-1:1). PRE0079 message: 'Default value {1} for field {0} violates declared {2}' (Diagnostics.cs:697); Fault message: 'Value {0} is outside the declared bounds [{1},{2}]' (Faults.cs:38)
- **Reasoning:** The fault message defines itself as a declared-band violation — which is rule sugar (spec 2.4) and recoverable at runtime on every lane: external value -> ingress governance refusal (runtime-api.md:656); computed value -> post-mutation sweep -> ConstraintsFailed with working-copy discard (spec 3A.4); default violating a band at Create -> Create's constraint sweep -> ConstraintsFailed (evaluator.md Create: 'if violations.Count > 0 return ConstraintsFailed'). Nothing aborts; can-it-compute is YES in every sub-case (literal, computed, input-fed — representability is NumericOverflow's name, not this one). The compile-time check behind PRE0079 (literal default vs literal bound) is a PROVEN violation and should stay as a static definition-contradiction rejection — same family as DefaultViolatesRule (spec 0.6 item 11) — but as rule-against-default checking, not fault prevention. Remove OutOfRange from the fault registry; its FaultCode has no can't-compute referent.
- **Mixed split:** Compile-side proven default-vs-bound contradiction: keep as static rule-enforcement rejection (0.6 item 11 family). Runtime band violation (any source): governance refusal, never a fault. No true-fault residue.
- **Runtime cite:** evaluator.md 7.1 Create 'if (violations.Count > 0) return new EventOutcome.ConstraintsFailed(violations)'; runtime-api.md:656 ingress bounds enforcement; result-types.md ConstraintsFailed 'Covers ALL post-fire constraints'

**Summary:** FAULT FLOOR ADJUDICATION (copy A). Decision test applied per code: a fault is a mid-evaluation abort with no recoverable typed outcome (only the Faulted trap, evaluator.md sec 9 / result-types.md:51); anything the working-copy discard handles (ConstraintsFailed/InvalidArgs/Unmatched/Rejected, spec 3A.4) is governance, not fault. RIGHT-SIZING CONSEQUENCES: (1) floor work owed = representability-overflow obligation (new), index-bounds/key-presence/temporal-overflow fault identities, position-completeness for the true-fault lanes (guards, because-interpolation, defaults, BUG-032), qualifier-source obligation, BUG-030, false-Proved ledger fixes; (2) scale back/reclassify = PRE0078/PRE0135/PRE0136 band prove-or-reject -> governance + flag-sound warnings (proven violations may stay static rejections as definition contradictions, 0.6 item 11 family); BUG-017/021 and the PRE0136 'no deferral' doc contract dissolve as floor items; remove OutOfRange/LengthBound/CountBound from the fault registry and the bijective core. (3) SPEC EDITS REQUIRED (owner decision, do not bundle silently): spec 0.7's fault-prevention sentence includes 'no result outside a declared bound' and Principle 11 lists 'constraint range impossibility' as a fault class — both bake the misclassification into the guarantee contract and must be amended for the reclassification to be canon; fault-system.md has registry drift (13 of 15 members, wrong UnexpectedNull linkage). Sequencing hypothesis VALIDATED with a refinement: floor-first is right, but the floor is smaller than built behavior in the band direction and larger in the representability/position direction — right-sizing is simultaneous subtraction and addition, then runtime, then the flag-sound universal layer as post-runtime gravy.
