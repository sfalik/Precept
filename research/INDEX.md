- [`architecture/compiler/bounds-only-constraint-enforcement-2026-06-05.md`](architecture/compiler/bounds-only-constraint-enforcement-2026-06-05.md) — evaluates the **"bounds-only"** hypothesis: should the compiler reason only over field intervals (narrow + default-vs-narrowed-interval + reject-unbounded-source) and **never** fold specific values, retiring the default value-fold (BUG-027)? Grounds the answer in the `NumericInterval` abstraction's expressiveness limit (a single closed `[Min,Max]` + difference-bound `x−y≤c` fact — structurally blind to `==`, `!=`, string/boolean rules, and 3-field sums), the shipped relational narrowing, and the full 77-file `samples/` corpus. **Key result (adversarial Q4):** the value-fold is **strictly necessary, not subsumable** — behavioral probes (`Compiler.Compile`, fresh build) show it rejects 7/8 genuinely-broken non-interval default shapes (equality, string, boolean, modulo, multi-field arithmetic) that bounds-only passes clean, each a Principle-11 hole; reject-unbounded-source is sound but over-rejects heavily on this corpus (214 unbounded `money` fields vs 10 bounded — forcing unnatural `max` ceilings on open-ended amounts) and rejects with the wrong reason (bound the source vs fix the default). Concludes bounds-only and the value-fold are **complementary** (interval owns the general runtime obligation; the value-fold owns the concrete default-configuration check), the "default-implies-a-pin" mitigation **is** value-reasoning in disguise (strictly weaker, numeric-only), and the computed-interval default check is a free sound win to ship regardless of BUG-027's fate. **Active — horizon groundwork**; feeds a `/design` decision on BUG-027's fate + the field-ref-bound enforcement architecture (BUG-020/021). Cross-links the sibling external-prior-art doc `interval-vs-value-evaluation-prior-art-2026-06-05.md`. All-Primary (Precept canon + source + probes).
- [`architecture/compiler/count-cardinality-bound-proof-survey.md`](architecture/compiler/count-cardinality-bound-proof-survey.md) — can static collection **count/cardinality-bound** checking (`mincount`/`maxcount`) be sound AND precise in forward abstract interpretation, given that a **dedup-set add** is a membership-dependent `+0-or-+1` delta? Surveys Dafny (membership-guarded `Set#Card` axiom: `!a[x] ⇒ +1`, `a[x] ⇒ +0`; multiset add unconditional `+1`), the SMT finite-sets+cardinality calculus (Bansal/Barrett/Reynolds/Tinelli, LMCS 2018 — membership×cardinality combination is the hard part, Venn-region blowup), SPARK formal containers (membership-conditional set `Insert`: `Length<Capacity OR Contains`, `Contract_Cases` split — membership as a *discharged precondition*), Liquid Haskell (membership without any cardinality measure), sized-types AI (Serrano et al. TPLP 2014 — size as inferred `[lo,hi]` interval, sound-but-incomplete), and classifies TLA+/Alloy out (bounded model-checking, not forward AI). Grounds the **BUG-018 count-delta fix**: current unconditional `+1` over-rejects `add x; add x` into `maxcount 1` (unsound for dedup kinds, contradicting `proof-engine.md:1719`). Recommends **Option 1** (per-kind sound count-only deltas: dedup-set add = upper`+1`/lower-unchanged, multiset/list/queue add = exact `+1`) as the soundness floor, with **Option 2** (bounded literal-distinctness tracking within a transition, solver-free) as an opt-in precision sharpening; the §0.7 runtime governance backstop is what licenses the sound-but-incomplete compile-time posture. **Cited.** Dafny-prelude / Bansal LMCS / Serrano TPLP / SPARK `.ads` legs Primary; AdaCore blog / Liquid Haskell / Alloy-TLA+ Secondary.
- [`architecture/compiler/interval-vs-value-evaluation-prior-art-2026-06-05.md`](architecture/compiler/interval-vs-value-evaluation-prior-art-2026-06-05.md) — external prior-art survey grounding the **bounds-only-vs-value-folding** decision (sibling/intended consumer: `bounds-only-constraint-enforcement-2026-06-05.md`). Sorts comparators onto a single **abstraction↔evaluation** axis: abstract interpretation's **interval domain** (Cousot POPL'77 soundness-via-approximation; Miné — interval is *non-relational*, `v∈[c1,c2]` only, cannot express `A+B==C`, "cheap but imprecise") and SPARK's lightweight **Interval** pass (subtype `range 0..100` = the bound) are the bounds-only pole; **refinement types + SMT** (Liquid Haskell — predicates restricted to the *decidable* QF-UFLIA fragment, subtyping = SMT validity, divisor typed `{v≠0}`) buy expressiveness with an opaque solver; **CUE** *blurs* value and bound (the owner's "values become bounds" — confirmed: a bound is "a logically infinite disjunction of concrete values," a default is checked by **subsumption** `d ⊑ v`, not evaluation); **Nickel** is the rejected value-evaluation pole ("contracts check that a value satisfies some property at run-time"). **Key results:** (1) reject-unbounded-source **is** the AI analogue of alarm-on-`⊤`, and "supply a bound" is well-precedented (SPARK add-a-precondition, Astrée supply-external-bounds-to-kill-alarms, LH type-the-divisor); (2) bounds-only's comprehensiveness ceiling is *exactly* the non-relational limit (octagon recovers `±x±y≤c` but not general 3-var/non-unit-coefficient linear relations — a named bounded gap); (3) **CUE shows value-folding need not be a separate mechanism** — checking default `5` against `>=10` is the lattice meet `5 & >=10 → ⊥`, i.e. interval-membership at a singleton `[5,5]`. Concludes Precept's bounds-only matches the interval-domain/SPARK-Interval model + octagon, solver-free by design (the "no opaque solver" line that separates it from LH/Dafny). **Active — horizon groundwork**; feeds the same `/design` decision as the sibling. Neutral spectrum survey across five points: **identical engine** (Rust one MIR interpreter for CTFE + Miri; Zig comptime = ordinary Zig at semantic-analysis time), **shared-definition restricted subset** (C++ `constexpr` — standard *mandates* "same result as an equivalent non-constexpr function" but explicitly carves out floating point as "unspecified"), **abstract soundly-related** (the interval/octagon domain — sound-by-approximation, never claims the runtime value; cited from the interval-vs-value sibling), **independently-implemented conformance-tested** (CompCert semantic-preservation theorem against one mechanized semantics; WASM reference interpreter + test suite), and the **drift pole** — the load-bearing empirical warnings: GCC/LLVM cross-compiler "constant folding must emulate the target machine's arithmetic" (host FP ≠ target FP) and Liquid Haskell's default unbounded-SMT-`Int` vs fixed-width machine-`Int` overflow gap. **Q-B (enforce-statically-vs-defer):** CUE/Dhall/C++ concretely evaluate non-abstractable constraints (equality/string/multi-field) on *constants* statically, but **only alongside a shared or mandated-equal runtime semantics**; Nickel is the runtime-deferral pole. Key synthesis: *concrete static evaluation and a shared/mandated-equal runtime semantics travel together — no surveyed system concretely evaluates statically while leaving an unrelated runtime evaluator free to disagree (that is the drift pole)*.
